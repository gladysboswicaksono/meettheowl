What JavaScript does in Course 2

JavaScript is the behaviour layer. In the demo stepper, it stores the step content, remembers which step is selected, reacts to clicks, and updates the page.

1

Stores the content

DEMO_STEPS is a list containing six content objects. Each object has a title and body.

2

Remembers the current step

demoActive is a memory box containing the number of the currently selected step.

3

Updates the screen

demoRender() finds HTML elements and replaces their displayed content with the current step.

4

Responds to the learner

demoSet(), demoGo(), and demoReset() respond to step, navigation, and reset button clicks.

Define the function and receive a direction

function demoGo(dir) {

demoGo is the custom function name. dir is a custom parameter name meaning direction.

Next calls demoGo(1), so dir becomes 1. Back calls demoGo(-1), so dir becomes -1.

Calculate the proposed new step

demoActive + dir

This asks: “If I move in that direction, which array position would come next?”

Next from position 2 2 + 1 = 3
Back from position 2 2 + -1 = 1

Calculate the last valid position

DEMO_STEPS.length - 1

Six steps have a length of 6, but array positions begin at 0. The valid positions are therefore 0, 1, 2, 3, 4, 5.

6 - 1 = 5, so position 5 is the upper limit.

Prevent movement beyond the last step

Math.min(DEMO_STEPS.length - 1, demoActive + dir)

Math.min() chooses the smaller of the last valid position and the proposed position.

On the final step, Next proposes 5 + 1 = 6. Math.min(5, 6) returns 5, so the stepper stays on the final step.

Prevent movement before the first step

Math.max(0, previousResult)

Math.max() chooses the larger of 0 and the result calculated inside it.

On the first step, Back proposes 0 + -1 = -1. Math.max(0, -1) returns 0, so the stepper stays on the first step.

Store the safe result and refresh the screen

demoActive = safePosition; demoRender();

The protected result is assigned to demoActive. This changes the course’s memory of the selected step.

demoRender() then reads that new value and updates the step buttons, title, body, counter, and navigation-button states.

In plain language: receive 1 or -1, propose a new position, keep it between the first and last valid positions, save it in demoActive, then redraw the stepper.
+1

Why pass 1?

The function adds dir to demoActive. Passing 1 moves one position forward. The Back button passes -1 to move one position backward.

R

Why call demoRender()?

Changing the memory variable alone does not redraw the page. The render function reads the new value and updates everything the learner sees.

Level 9 theory

Schedule work for five seconds later

setTimeout() asks the browser to run a function once after a delay. JavaScript measures that delay in milliseconds, so five seconds is 5000 milliseconds.

The smallest five-second timer Concept preview
let nextButtonPromptTimer = null; nextButtonPromptTimer = setTimeout(() => { nextButtonPromptVisible = true; showNextButtonPrompt(); }, 5000);

The timer variable begins empty

let nextButtonPromptTimer = null;

null means there is currently no scheduled timer stored in the variable.

setTimeout() schedules one future action

The first argument is the function to run later. The second argument is the waiting time in milliseconds.

The browser returns a timer ID

That returned value is stored in nextButtonPromptTimer. It is a reference to the scheduled work, not the five-second count itself.

The delayed function changes state and updates the screen

After five seconds, it sets nextButtonPromptVisible to true and calls a custom function that applies the visual class.

Why cancellation matters

Suppose the learner clicks Next after two seconds. The guidance is no longer needed. Without cancellation, the old timer would still finish three seconds later and show an irrelevant prompt.

Cancel the scheduled work Concept preview
function cancelNextButtonPromptTimer() { clearTimeout(nextButtonPromptTimer); nextButtonPromptTimer = null; }

4. Each function has one main responsibility

renderNextButtonPrompt() synchronizes state with HTML

classList.toggle( 'is-showing-next-prompt', nextButtonPromptVisible );

With a second Boolean argument, classList.toggle() is explicit: add the class when the Boolean is true; remove it when false.

showNextButtonPrompt() handles normal timer completion

It changes visibility to true, sets the timer reference to null because the scheduled work has finished, and renders the new state.

hideNextButtonPrompt() changes visibility to false

It then renders that state, which removes the parent class. CSS responds by hiding the prompt and fading out the dim layer.

cancelNextButtonPrompt() cancels unfinished work

clearTimeout() receives the stored timer ID. Resetting the variable to null records that no timer is now pending.

scheduleNextButtonPrompt() prevents duplicate timers

It cancels any earlier timer before scheduling a new one. The browser stores the new timer ID in nextButtonPromptTimer.

demoGo() dismisses guidance before navigation

It first cancels an unfinished timer and hides a visible prompt. It then changes demoActive and calls demoRender() to update the stepper content.

Start the timer when the interaction is actually visible

IntersectionObserver is a browser feature that reports when an observed element enters or leaves the viewport. We will use it to begin the five-second wait only when at least half of the browser mockup is visible.

The visibility observer Next implementation
function handleDemoStepperVisibility(entries) { const [entry] = entries; if (entry.isIntersecting) { scheduleNextButtonPrompt(); } else { cancelNextButtonPrompt(); hideNextButtonPrompt(); } } const demoStepperObserver = new IntersectionObserver( handleDemoStepperVisibility, { threshold: 0.5 } ); demoStepperObserver.observe( document.getElementById('demo-stepper') );

IntersectionObserver is the official browser feature

handleDemoStepperVisibility and demoStepperObserver are custom names chosen for this project.

The callback receives an array of observation reports

entries is an array. Because we observe one element, const [entry] = entries; takes its first report and gives it the clearer singular name entry.

entry.isIntersecting is a Boolean

It is true when the observed element meets the visibility threshold and false when it does not.

threshold: 0.5 means 50% visible

The callback changes state when roughly half of the observed browser window crosses into or out of the viewport.

Entering and leaving have opposite cleanup behavior

Entering schedules the timer. Leaving cancels unfinished work and hides guidance that is already visible.

Level 11 theory

Remember that the learner has dismissed the guidance

Visibility state answers whether the prompt is showing right now. Dismissal state answers a different question: should this page session ever schedule it again?

V

nextButtonPromptVisible

Temporary display state. It moves between true and false whenever the prompt appears or disappears.

D

nextButtonPromptDismissed

Session decision state. Once true, new prompt timers should not be scheduled again during that page load.

The one-time guard JavaScript
let nextButtonPromptDismissed = false; function scheduleNextButtonPrompt() { if (nextButtonPromptDismissed) return; cancelNextButtonPrompt(); nextButtonPromptTimer = setTimeout(showNextButtonPrompt, 5000); }

The new Boolean begins false

The learner has not dismissed anything yet, so the observer may schedule the guidance when the mock browser becomes visible.

The guard clause stops unnecessary work early

if (nextButtonPromptDismissed) return;

When dismissal is true, return exits the schedule function immediately. No timer is created.

A dedicated dismiss function coordinates cleanup

It records the learner’s decision, cancels pending work, and hides current guidance in one reusable place.

The dismissal function One coordinated action
function dismissNextButtonPrompt() { nextButtonPromptDismissed = true; cancelNextButtonPrompt(); hideNextButtonPrompt(); }
This memory lasts only until the page reloads. We are deliberately not using localStorage: remembering across visits would require a product decision about whether the guidance should ever return.
